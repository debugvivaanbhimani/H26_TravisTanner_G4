# DepExit — Dependency Exit Capsules, verified

**DepExit** is an open-source, AI-powered developer tool that finds at-risk dependencies in a
Python repository, plans their replacement with **Gemma 4**, *actually executes* the migration
against the real test suite, repairs it in a self-healing loop, and packages every piece of
evidence into a reusable **Dependency Exit Capsule**.

Core principle: **the AI never states facts.** Plain code observes and executes; Gemma reasons.
Every field in the capsule is tagged with where it came from:

| Tag | Meaning |
|---|---|
| `OBSERVED` | Read from repository files, the Python AST, the PyPI API or GitHub. Deterministic. |
| `VERIFIED` | Produced by installing dependencies in an isolated environment and executing tests. |
| `AI` | Generated by Gemma 4 — a recommendation or hypothesis, never a fact. |

And the AI's output is itself checked: every risk claim must cite the id of a real observed
indicator, and every proposed replacement is looked up on PyPI / the stdlib. Claims that fail
are flagged as **ungrounded** in the capsule.

## Pipeline

```
 repo ─► 1 SCAN (OBSERVED)             manifests, AST usage: imports, calls, private API, monkey-patches
       ─► 2 BASELINE (VERIFIED)        clean Python 3.12 venv, import probes, full test run
                                       + alternate-manifest run when requirements.txt ≠ pyproject.toml
       ─► 3 RISK (OBSERVED)            PyPI metadata, GitHub status, conflicts, undeclared deps,
                                       failures traced to the library they originate in
       ─► 4 TRIAGE (AI → checked)      Gemma 4 picks action + replacement + steps, citing evidence ids;
                                       grounding check rejects invented evidence / non-existent packages
       ─► 5 MIGRATE (AI + VERIFIED)    Gemma writes edits + a behavioural-equivalence test
                                         → equivalence test run on the ORIGINAL code
                                         → edits applied in a sandbox, full suite run on the REPLACEMENT
                                         → failures fed back to Gemma, up to N repair attempts
       ─► 6 COMBINE (VERIFIED)         all verified migrations applied together, suite re-run
       ─► 7 CAPSULE                    capsule.json · capsule.md · report.html · patches/ · tests/ · replay.sh
```

Nothing is hard-coded for any repository: point it at any Python repo with a pytest suite.

## Quick start

Requirements: Python 3.12 or 3.13, [`uv`](https://docs.astral.sh/uv/) (`pip install uv`), git.

```bash
pip install -r requirements.txt
cp .env.example .env            # then put your Google AI Studio key in it
python -m depexit https://github.com/rishrek/LinkWatch --out capsule
open capsule/report.html        # or capsule/capsule.md
```

Useful flags:

| Flag | Purpose |
|---|---|
| `--only jinja2,appdirs` | migrate only these dependencies (fast live demo) |
| `--max-fix 2` | AI repair attempts per dependency |
| `--workers 3` | dependencies migrated in parallel |
| `--no-ai` | observed + verified evidence only, no Gemma |
| `--no-migrate` | analysis and recommendations, skip executing replacements |
| `--python 3.13` | target interpreter (default 3.12) |

## The Dependency Exit Capsule

`capsule/` contains:

- `capsule.json` — machine-readable, schema `dependency-exit-capsule/1.0`. For every dependency:
  dependency details, risk indicators, usage locations (`OBSERVED`); proposed replacement,
  migration steps, suggested tests, expected gaps (`AI`); checks on the AI output (`OBSERVED`);
  executed test results per attempt, comparison, observed compatibility gaps (`VERIFIED`);
  open concerns and limitations.
- `capsule.md` — the same, human-readable.
- `report.html` — self-contained interactive report (works offline).
- `patches/<dep>.patch`, `patches/combined.patch` — the verified migrations as `git apply`-able diffs.
- `tests/test_depexit_<dep>.py` — AI-written behavioural-equivalence tests, already run on both sides.
- `ai_transcript.jsonl` — every Gemma call: purpose, model, latency, prompt hash, raw response.
- `replay.sh` — re-runs original vs replacement on any machine to reproduce the evidence.

## AI model disclosure

| | |
|---|---|
| Model | **Gemma 4** — `gemma-4-31b-it` (instruction-tuned, 31B) by default; override with `GEMMA_MODEL` or `--model` |
| Version | as served by the Gemini API at run time; the exact model id is recorded in every capsule and transcript entry |
| Access method | Hosted API: Google AI Studio / Gemini API, `POST generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` |
| Terms | [Gemma Terms of Use](https://ai.google.dev/gemma/terms), [Gemma Prohibited Use Policy](https://ai.google.dev/gemma/prohibited_use_policy), [Gemini API Additional Terms](https://ai.google.dev/gemini-api/terms) |
| Role | Risk triage, replacement selection, migration planning, code edits, equivalence-test writing, repair of failed migrations |

## Limitations

- Verification is only as strong as the repository's test suite plus the generated equivalence
  tests; untested code paths are listed as open concerns in each capsule.
- Python + pytest repositories only. Requirements are read from `requirements*.txt`,
  `pyproject.toml` and `setup.cfg`.
- Registry signals (release age, inactivity) are indicators, not proof that a package is unsafe.
- Security vulnerabilities are intentionally out of scope for this version.
